# 微信论文工作台

这是 clawbot 内部的独立扩展层，构建时只改生成副本。原仓库代码、Zotero 数据库和 PDF 均保持原样。

启用后，微信主会话可列分类、按标题/作者/年份检索（含独立 PDF）、打开本机 PDF、读取页码正文和页面图像、创建连续研读计划，并把每部分导出为中文 Markdown/PDF。收到或引用 PDF 后登记为不透明 sourceId，不允许通过论文工具任意指定其他文件路径。同名收件保存为唯一文件，原文件名用作显示标题。主会话工具不会全局挂载。

在“论文阅读规则”中填写已有 Markdown 路径，每个任务重新读取，记录规则哈希。默认分成 2–5 部分，原文顺序；用户说继续后接着读。正常问答仍只回答具体问题。补充材料以独立附件列出，在对应正文论证处查看，不能把未读到的参数猜出来。最终分析使用 DSH 当前模型（包括已登录的 ChatGPT OAuth），不需要复制 OAuth 凭据或另建 ChatGPT 网页上传流程。

所有输出在独立论文工作区。完成后由原 `send_wechat_file` 工具回传；必须根据发送结果说明成功与否。每部分文件以唯一名称保存，不覆写旧报告。中文 PDF 嵌入字体，公式使用本机 MathJax 排版，Markdown 保留原始 LaTeX。较大 PDF 自动按页分卷，每卷不超过 850,000 字节，完整 PDF 与 Markdown 仍在本机保留。单页超过该限制时先发送 Markdown，不能声称 PDF 已送达。

模型报告会再对照当前范围的正文检查遗漏，必要时对具体段落修订，最多两轮。替换需精确匹配唯一原句、互不重叠，保留其他段落；引用公式保留原论文关系符号，近似条件另行解释。各次诊断稿保存在任务目录，未通过检查不会变成正式报告或推进进度。通过模型检查仍不代表科学结论已经人工核验。跨页图会获取对应页面和图注，不把后续正文混入当前部分。正文与选定补充说明中明确引用的 Supplementary Fig./Fig. S 图，也会在已选择的补充附件中查找对应图页，补齐模型页码计划可能漏选的图像。所选图像都会提供给模型或分批视觉调用，报告记录真实来源与页码。

导出失败时保留正文草稿，进度不推进。设置卡片的“重试导出（复用草稿）”或微信 `paper_retry_export` 复用原草稿，不重复调用模型。重启后继续任务会检查原 PDF、规则哈希和模型路由；文件或规则改变时需要新建任务。其他联系人及普通 DSH 会话不能读取个人库或研读进度。

微信示例：

- “看看 Zotero 有哪些分类，再列出 FeSe 分类里的论文。”
- “找我选中的那篇论文，按我的规则从第一部分开始，整合补充材料，报告发文件。”
- “继续上一份论文。”
- 直接发 PDF，并说“按我的论文研读规则分析，结果发 PDF 和 Markdown”。

设置卡片提供分类和标题检索、当前任务、分析及继续按钮，支持取消当前网页请求和下载生成的报告。下载只允许任务清单里已有的报告，不能指定其他本机文件。网页分析只生成本地文件，微信发送仍由真实会话中的原发送工具执行。原有设置按论文、聊天与记忆、主动互动、连接与模型、高级设置分组，支持关键词筛选。

当前边界：单份 PDF 不超过 80 MB；自动计划每份附件最多 100 页，最多六份正文/补充附件；每次原文读取 1–25 页，自动研读通常分 2–5 个连续部分。长书使用页码工具选章节；超过单次范围的“一次讲完”暂不支持。扫描版会明确标记需要 OCR，本版没有自动 OCR。需要 Python 的 pdfplumber/reportlab/pypdf、Poppler 和中文字体；配置脚本可定位当前电脑的 Codex 附带依赖，不改 Zotero 原件。

Zotero/DSH/电脑需运行并有网络，才能在外出的手机微信里使用。睡眠、电脑离线、微信发送上下文过期会导致任务等待或发送失败；重新开机后可从保存的任务继续。
