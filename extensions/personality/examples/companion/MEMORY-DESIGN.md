# 微信陪伴记忆扩展设计草案

状态：设计与模板；尚未安装记忆后端，尚未接入 clawbot 运行时。

## 组件职责

DSH 继续提供模型、工具、会话和权限。clawbot 扩展负责识别微信来源、用户隔离、记忆范围、相处规则和原有设置页面。记忆后端负责持久化、检索与更新；优先评估 MemOS 的 DSH 适配器，不能仅凭安装成功判断兼容。

## 每轮处理

1. 确认微信账号、联系人和会话来源，解析事件时间。只处理获准的微信对话。
2. 根据当前消息检索少量相关记忆，按身份隔离，并将记忆作为历史数据提供给模型。超时继续正常对话。
3. DSH 处理对话与工具调用，clawbot 使用现有发送路径回复。
4. 将本轮待整理事件写入持久化队列；使用来源事件 ID 去重，后台提取并合并记忆，避免阻塞下一轮回复。
5. 用户明确要求“记住、更正、忘记”时优先执行相应操作。仅在写入或删除成功后确认完成；自动后台整理可能晚于下一条消息。

新消息来自 clawbot 插件时，需检查 MemOS 的 direct-user 来源过滤是否接受；否则在隔离适配层显式接入。不能为了捕获微信消息而把所有插件通知都当作用户消息。

## 记忆分类

| 类别 | 例子 | 更新方式 |
| --- | --- | --- |
| 长期画像 | 明确表达的饮食偏好、沟通习惯 | 新信息替代旧状态，保留时间与来源 |
| 近期经历 | 近期项目进度、用户分享的重要事件 | 用绝对时间；设置保留期，允许后续续接 |
| 跟进事项 | 用户希望下周讨论某件事 | 记录状态；只有获准调度才能主动发消息 |
| 相处规则 | 用户说“先听我讲，不要马上给建议” | 规则候选可预览、启用、撤销 |
| 任务经验 | 某个工具方案成功或失败的原因 | 依据真实工具结果总结，可进一步形成 skill |

单条结构至少包括：id、微信账号/联系人作用域、类别、内容、来源事件 ID、发生时间、记录时间、有效期、确认状态、替代记录 ID、修订号。画像不根据一次情绪或模型猜测直接定性。

## 可编辑文件

- `agent.md`：用户控制的基本身份与行为规则，不随自动总结重写。
- `USER.md`：确认的用户画像快照。
- `RELATIONSHIP.md`：双方真实经历与明确相处偏好摘要。
- `EPISODES.md`：按时间记录的近期事件摘要。
- `LEARNED-RULES.md`：待审核与已启用的沟通规则。

上述快照不手工维护两份事实源：数据库保存结构化记忆，界面修改通过后端写入，再生成带修订号的文件。行为文件需要扩展显式加载；文件名称本身不会赋予模型工具、记忆或调度能力。

## 原有 clawbot 设置页面

新增自动记忆开关、记忆范围、近期记忆保留期、整理频率/调用预算、记忆列表和检索预览。列表支持查看来源、修改、更正、删除和排除自动重学。删除应同步处理结构记录、检索索引和导出快照；备份与原始聊天的保留范围需明确显示。

调试页显示本轮检索到的记忆、候选规则与整理失败原因；不显示 OAuth token、密钥或其他联系人信息。MemOS 自带独立 Viewer 不等于已集成到 clawbot 页面，需要适配层接入。

## 接入前验证

- 当前 DSH 0.2.0-rc.2 与 MemOS 文档验证的 0.1.0-rc.5/rc.6 存在版本差异，需要验证生命周期、事件结构与公开 llm 服务。
- 核实 Windows 安装目标与原生 SQLite/ONNX 依赖，先做隔离测试，避免影响现有 DSH 与微信监听。
- 确认微信来源能够触发捕获和检索；确认联系人之间、普通 DSH 会话与微信之间不串记忆。
- 验证新偏好覆盖、更正与忘记、相对日期、重启恢复、重复事件、故障降级以及后台队列重放。
- 复用 DSH 模型进行整理会额外消耗对应额度；本地数据库不意味着模型推理不出网。
